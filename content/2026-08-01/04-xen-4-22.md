Xen doesn't get much attention outside infrastructure circles, but the
open-source hypervisor has spent two decades underneath a striking
share of the internet — including, for years, the backbone of Amazon
Web Services — as well as inside embedded and automotive systems that
never advertise what's running them. On July 30, the Xen Project
released version 4.22, a genuine modernization pass rather than a
maintenance release
([Linuxiac](https://linuxiac.com/xen-4-22-hypervisor-brings-new-x86-features-and-better-arm-power-management/);
[Linux Foundation](https://www.linuxfoundation.org/press/xen-project-releases-xen-4.22-strengthening-open-source-virtualization-for-cloud-embedded-and-automotive-systems-1)).

On x86, Xen 4.22 adds support for FRED — Flexible Return and Event
Delivery — a newer processor mechanism for handling interrupts and
system calls more cleanly than the decades-old scheme it replaces,
alongside AMD's Bus Lock Threshold feature to curb performance hits
from repeated atomic instructions. Arm gains guest suspend-and-resume
support through the Power State Coordination Interface, useful for
power-constrained and embedded deployments, plus an updated Arm
Firmware Framework and continued work toward Armv8-R support for
safety-critical systems. Xenstore, the hypervisor's shared
configuration database, now supports per-domain quotas and
watch-depth limits, closing off a class of problem where one greedy
virtual machine could crowd out the resources every other guest on
the host depends on.

The release also leans into an audience Xen has increasingly courted:
automotive and embedded developers who need to prove a system behaves
correctly, not just that it usually does. New QEMU-based
Software-in-the-Loop tooling supports repeatable fault-injection
testing, and new non-instrumented code-coverage tooling measures test
completeness without the timing distortions that instrumentation can
introduce — the kind of unglamorous, exacting infrastructure that
underpins certifying a hypervisor for use in a car.

None of this will make headlines the way a flashy product launch
does, and that's rather the point of open infrastructure done well:
it improves steadily, in public, maintained by a community rather
than a single vendor, and the people who benefit most from it — cloud
operators, embedded engineers, the drivers of cars they'll never know
are running Xen — mostly never have to think about it at all.
