Nobody writes a manifesto about a better list view, but a lot of a developer's day is spent scrolling through one. On September 10, GitHub rolled out a [refreshed repository pull requests page](https://github.blog/changelog/2026-09-10-refreshed-repository-pull-requests-page-in-public-preview/) in public preview, aimed squarely at that daily grind of finding the PR that actually needs attention.

The new page adds content-assisted filtering, advanced search that understands `AND` and `OR` operators and nested queries, a collapsible sidebar for the filters people reach for constantly, and a compact presentation mode that fits more pull requests on screen at once. It also surfaces status checks and unread updates more clearly, so the question "does this one need me right now" gets answered without a click.

It's in public preview for all GitHub users, with a few known gaps — milestones aren't shown yet, bulk updates aren't supported, and custom saved views don't carry over — and a badge that lets anyone flip back to the classic experience while GitHub collects feedback. None of it is flashy. It's the kind of improvement that just makes the tool everyone already uses a little less annoying, which, multiplied across millions of developers checking their PR lists every morning, adds up to real time given back.
