The most useful software updates are often the ones that don't announce
themselves loudly. GitHub's July update to Copilot in Visual Studio,
shipped July 30, is a batch of exactly that kind of improvement —
nothing that will make a keynote, but several things that will save
real developers real time by the end of the week
([GitHub Changelog](https://github.blog/changelog/2026-07-30-github-copilot-in-visual-studio-july-update/)).

The headline feature lets a developer select code in the editor,
right-click, and choose "Review Selection" to get inline comments from
Copilot's code-review model on the spot, instead of waiting for a pull
request to trigger one. A new agent, in public preview and built on the
same Copilot SDK that powers the Copilot CLI, is aimed at shorter,
easier-to-scan responses with less back-and-forth than earlier versions.
Teams working in .NET and Azure get built-in, expert-authored skills
they can turn on in the tool picker rather than configuring from
scratch. And organization owners can now set custom instructions once,
at the organization level, that automatically apply across every
repository — sparing each individual developer from re-explaining the
same coding conventions to the same assistant.

Taken individually, none of these is a breakthrough. Taken together,
they're the shape most software improvement actually takes: not a
single dramatic leap, but a tool that fits a little better into the
day's work than it did the week before.
